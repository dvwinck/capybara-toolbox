## [Unreleased]

## [0.2.0] - 2026-10-23

### Added
- `scan --lang en|pt-BR` chooses the language of the cards: field labels, titles, effects, the group card, the "do not touch" reasons, the button wording (`labels`), the `confirm` texts, the subtitle and the age wording. The language is written to `batch.json` (`lang`, so the panel opens in it) and to `scan.json`. `check` rejects any other value in `scan.json`; an older scan without `lang` is read as English.
- The pt-BR cards are now written with accents.
- **Every command takes `--lang en|pt-BR`** for its messages (`scan`, `check`, `apply`, `restore`). Without it, `check`, `apply` and `restore` speak the language recorded in `scan.json`; `scan` uses one language for its cards and its output alike.
- **`CAPYBARA_LANG`** (`en` or `pt-BR`) is the default language when no flag and no recorded language decide; any other value is ignored. Every Capybara Toolbox tool that speaks pt-BR reads the same variable; publish-check prints English only.

### Changed
- The card of a worktree with a detached HEAD no longer shows a merged-PR field (0.1.1 showed "sem PR mergeado" there, though a worktree with no branch has no PR to look up); every other card keeps its fields.
- **The default is English**, for the cards and for the command line. A `scan` without `--lang` (and without `CAPYBARA_LANG`) writes English cards and prints English lines; pass `--lang pt-BR` for the Portuguese ones. The pt-BR command-line text is the accent-free Portuguese of 0.1.1, except that a count of one now takes the singular (`1 item`, `1 apagado`).
- In English `NAO TOCAR:` reads `DO NOT TOUCH:`, the error prefix is `error:` (pt-BR `erro:`) and the scan summary line ends with `; language <lang>` (pt-BR `; idioma <lang>`). The tags `TIDY-BOARD DIR:`, `TIDY-BOARD ITENS:`, `TIDY-BOARD:`, `APPLY:`, `RESTORE:` and `ok:` and the action words `deleted`, `skipped` and `would-delete` are the same in both languages. The `--help` text is English.
- The inventory holds codes, not text: the reasons an item is never offered, the merged-PR note and the remote note are rendered from a per-language table when the cards are built. `apply`, `restore` and `applied.json` are unchanged in shape: they read ids, shas and proofs, never a label; the `reason` of a skipped item is written in the language of the run.
- Requires ar-board 1.4.0 (the vendored engine) for the panel to honour `lang`.

## [0.1.1] - 2026-10-15

### Changed
- The skill and its examples were rewritten in English for LLM use (the panel and script output stay in Portuguese). Behaviour and script are unchanged apart from the version.

## [0.1.0] - 2026-10-14

### Added
- First release: the `tidy-board` skill and `tidy_board.py` (`scan`, `check`, `apply`, `restore`).
- `scan` reads one repository (no fetch, no network) and writes an ar-board batch plus a `scan.json` sidecar: one card per local branch, linked worktree and stash that looks finished, each with its proof level (P1 ancestor of the base, P2 merged PR via `gh`, P3 equivalent patch or squash, P4 unique work), the last commit, ahead/behind, the unique commits and the PR.
- A group card approves every P1/P2 item at once; an own decision on an item (Manter or Depois) always wins over the group.
- Items that exist in one place only (P3, P4, stashes) need a second press to approve, and `apply` writes `refs/tidy-board/backup/...` before deleting them.
- `apply` re-verifies each approved item at deletion time (ref still exists, same sha, not checked out, still merged for P1, worktree clean), never forces a worktree removal and never touches `origin`; the only network access is `gh`, read-only, to re-check P2 items once per run (an item whose PR it cannot confirm is skipped). It writes `applied.json`.
- `restore` recreates a deleted branch, stash or detached worktree head from its backup ref. Items proved as merged (P1/P2) have no backup (their commits are in the base): it refuses and prints the `git branch` to run by hand.
- Never offered: the base (however `--base` is spelled), the current branch, branches checked out in a worktree, and worktrees with tracked changes or untracked files. A clean worktree holding git-ignored files is offered with a second-press confirmation, outside the group card.
- `apply` derives what to back up and what to delete from the live state and the re-verified proof, never from flags in `scan.json`; a branch is deleted with a conditional `git update-ref -d`; `applied.json` is written even if a run is interrupted; ref names are resolved in full, so a tag cannot stand in for a branch.
- A generated byte copy of the ar-board engine (`capy_board.py`, ar-board 1.3.0) ships inside the skill; `tools/sync.py --check` fails on drift.
